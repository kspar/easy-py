## Context

- **easy-py** (this repo) — Python SDK: Keycloak auth via local Flask server + browser, REST calls to the core API.
- **easy-thonny** (`../easy-thonny`) — Thonny plugin (`thonny-lahendus` on PyPI, v9.2.0) that consumes easy-py.

**Verified by live probes / core repo inspection (don't re-derive):**
- Prod+dev discovery documents advertise the same `/auth/realms/master/protocol/openid-connect/{auth,token,logout}` endpoints — only `keycloak.js` is gone. Refresh (`ez.py:116`) and logout (`ez.py:486`) paths still resolve (latent risk only).
- Prod token endpoint **403s browser requests from `http://127.0.0.1:*` origins** (Web Origins/CORS) but processes Origin-less (native/Python) requests normally → vendored keycloak-js would NOT work without IdP config changes; **hand-rolled PKCE works against prod today**. (User chose hand-rolled.)
- Prod accepts `redirect_uri=http://127.0.0.1:<any port>/login` on the authorization endpoint. **Dev does not** (`Invalid parameter: redirect_uri`), and dev has no `dev.lahendus.ut.ee` client at all (dev v4.0 SPA config.json uses clientId `lahendus.ut.ee`) → **dev login testing needs kspar to fix dev IdP client config; flag this, don't block on it**.
- Logout endpoint on prod+dev accepts `client_id` + `post_logout_redirect_uri` (302). User chose minimal logout fix (no id_token storage).
- v4.0 response shapes confirmed in `../easy/core/src/main/kotlin/core/ems/service/assessments.kt`:
  - `TeacherActivityResp`: `id, submission_id, submission_number, created_at, grade?, edited_at?, feedback_md?, feedback_html?, teacher{id,given_name,family_name}` (flat, nullable).
  - `InlineCommentResp`: `id, submission_id, submission_number, teacher{...}, created_at, edited_at?, line_start, line_end, code, text_md, text_html, suggested_code?` — **no `type` field** (dropped in EZ-1777; `suggested_code != null` is the discriminator; `""` normalized to null server-side). Wrapper: `{"inline_comments": [...]}`.
- Release mechanics (EZ-1803 comment): `EasyExerciseProvider._update_required` compares **major version only**, and `_get_versions` requires **exactly 3 numeric components** → plugin must ship as exactly **`10.0.0`**.
- easy-py's `handle_response` (`easy/util.py:29`) instantiates only the **top-level** dataclass; nested list items reach the plugin as raw dicts. Nested dataclasses are documentation. Warning is logged for unknown top-level fields; missing fields become None (tolerant both ways).

## Part 1 — easy-py changes (release as 0.8.0)

### 1a. EZ-1803: replace keycloak-js flow with hand-rolled authorization-code + PKCE

Design validated by Plan agent against installed Flask 2.0.3 / Werkzeug 2.0.3 sources: the auth server runs **single-threaded** (`app.run(host, port, False, False)` = debug/load_dotenv; no `threaded` option → handlers serialized, no locks needed — do NOT add `threaded=True`); `environ['werkzeug.server.shutdown']` exists in 2.0.x (removed in 2.1 — keep the pins) and the response is fully written before shutdown; Flask auto-adds HEAD to GET routes and runs the view for it.

Files: `easy/ez.py`, `easy/util.py`, `easy/auth-templates/` (delete `login.html` + `keycloak.json`, add `auth-result.html`), `setup.py`.

**Step 1 — endpoint derivation (pure refactor + new params).**
- `Ez.__init__` gains trailing params (backward compatible; `easy_provider.py:39-49` and `test.py:58-62` untouched): `idp_realm_path: str = '/auth/realms/master'` (normalise: `'/' + value.strip('/')`) and `logout_redirect_url: str = None` → defaults to `https://{idp_client_name}` (needed because thonny-easy dev must split site host from client id, see 2d).
- `RequestUtil.__init__` derives once: `oidc_base = f'{idp_url}{idp_realm_path}/protocol/openid-connect'` → `self.idp_auth_url/idp_token_url/idp_logout_url` (`+'/auth'`, `'/token'`, `'/logout'`). Immutable after init → safe to read from route closures.
- `_refresh_using_refresh_token` (`ez.py:116`) uses `self.idp_token_url`; extract `_persist_tokens_from_idp_body(body)` from `ez.py:121-127` (reused by the exchange).
- `logout_in_browser` (`ez.py:482-488`): keep token clearing first; then `webbrowser.open(f'{idp_logout_url}?' + urlencode({'client_id': ..., 'post_logout_redirect_uri': logout_redirect_url}))`.

**Step 2 — PKCE helpers in `easy/util.py`** (stdlib: `secrets`, `hashlib`, existing `base64`): `pkce_s256_challenge(verifier)` (`urlsafe_b64encode(sha256(...)).rstrip(b'=')`) + `generate_pkce_pair()` (`secrets.token_urlsafe(64)` → 86 chars, RFC 7636-legal). Two functions so the RFC 7636 Appendix B vector is unit-testable.

**Step 3 — new flow in `ez.py`.** Extract `RequestUtil._create_auth_app(port) -> Flask` (unit-testable via `app.test_client()`); `start_auth_in_browser` creates the app only inside the `not is_server_active()` branch (plugin retry loop reuses the running app), polls readiness on **`/health`** with `requests.head(..., timeout=2)` (current poll HEADs `/login` expecting 200 — would break on 302 AND generate state as a side effect), then opens `/login`.
- Closure locals in `_create_auth_app`: `pending_states: dict[state → verifier]` and `redirect_uri = f'http://127.0.0.1:{port}/login'`. **Critical pitfall:** never build redirect_uri from `self.auth_server_port` inside handlers — the callback calls `clear_server()` first (nulls the port) and the token exchange's `redirect_uri` must byte-match the authorization request.
- Routes: keep `/shutdown` verbatim; delete `/keycloak.json` + `/deliver-tokens`; add `/health` (200); `/login` GET with two branches:
  - **Fresh** (no `code`/`error` in args): generate pair + `state = secrets.token_urlsafe(32)`, store in `pending_states`, `redirect()` to `idp_auth_url` with `urlencode({client_id, redirect_uri, response_type: 'code', scope: 'openid', state, code_challenge, code_challenge_method: 'S256'})`. No `nonce`/`response_mode` needed. Multiple opens = multiple dict entries; pop-on-use; dict dies with the server.
  - **Callback** (`code` or `error` present — only this branch tears down): `clear_server()` first, `shutdown_server()` in `finally` (mirrors `/deliver-tokens`, exactly-once teardown). Order: `error` in args → fail; `pending_states.pop(args.get('state'), None)` is None → fail; no `code` → fail; `requests.post(idp_token_url, data={grant_type: 'authorization_code', client_id, code, redirect_uri, code_verifier}, timeout=TIMEOUT)` non-200 → log status+body (error JSON only — NEVER log a success body, it contains tokens) → fail; else `_persist_tokens_from_idp_body(r.json())` → success. Catch-all `except Exception` → fail page. Success/fail both return 200 pages.
- Behavior change (improvement, note in release): user-cancel at Keycloak now ends the auth server immediately → plugin's `is_auth_in_progress(300)` returns right away instead of waiting out the timeout. Second-tab callback after first tab wins gets browser connection-refused (server gone by design; acceptable, ≈ today's failed second `/deliver-tokens`).

**Step 4 — template.** One `auth-result.html` (Jinja, autoescaped — safer than today's injection into a JS string literal): `{{ message }}` + `{% if close_window %}<script>window.close();</script>{% endif %}`. Success → `close_window=True`, fail → `False`. Delete `login.html`, `keycloak.json`. `MANIFEST.in`/`package_data` glob the dir — no packaging edits.

- No new dependencies; keep `flask~=2.0.3`/`werkzeug~=2.0.0` pins (shutdown mechanism removed in werkzeug 2.1).
- Claims: same client + `scope=openid` (keycloak-js's default) → `given_name`/`family_name`/`preferred_username`/`email` come from the client's default scopes; `check_in` and the plugin keep working.
- Release hygiene: stale `build/`/`dist/` exist — clean `build/` before `build.cmd` so deleted templates don't leak into the wheel.

## Part 3 — Python 3.14 / Thonny 5 compatibility (found after plan approval, not in any issue)

Thonny 5 bundles **Python 3.14.4** and installs plugins into `%APPDATA%\Thonny\plugins\Python314\site-packages`. Two independent failures there, both fatal to login and neither covered by EZ-1803:

**3a. The plugin crashed before it rendered anything.** `easy_provider.py` imported `pkg_resources`, which ships with setuptools — absent from Thonny's bundled Python, so opening the view raised `ModuleNotFoundError`. Replaced with stdlib `importlib.metadata.version("thonny-lahendus")`.

While in that function: `_update_required` runs at the top of *every* page render and had no error handling, so a PyPI outage, missing metadata, or an unexpected version string turned every page into the error page. It is now wrapped in try/except (logs, skips the check, backs off 10 min) and parses only the major component instead of unpacking exactly three. A `timeout=10` was added to the PyPI request. **The published version must still be exactly `10.0.0`** — installed 9.2.0 clients run the *old* strict parser.

**3b. Werkzeug 2.0 cannot run on Python 3.12+.** `werkzeug/routing.py` calls `ast.Str`, removed in Python 3.12, while compiling URL rules — so `Flask(__name__)` itself raises `AttributeError`. easy-py pinned `werkzeug~=2.0.0` solely to keep the `environ['werkzeug.server.shutdown']` hook (removed in Werkzeug 2.1), so the pin that protected the shutdown mechanism was exactly what broke the SDK on modern Python.

Fix: the auth server is now built with `werkzeug.serving.make_server(host, port, app, threaded=False)` and run via `serve_forever()`; routes stop it by calling `server.shutdown()` **from a separate thread** (inline would deadlock — the loop cannot exit while the handler runs). `_create_auth_app(port, shutdown_server)` takes the shutdown callable as a parameter, which also removes the environ-injection hack from the tests. The `flask.cli` banner-suppression poke is gone with `app.run`.

Floors raised to `flask>=3.0` / `werkzeug>=3.0` (and `python_requires='>=3.9'` in both repos). The code works on Werkzeug 2.0 too — verified — but a `>=2.0` floor would be counted as satisfied by the broken 2.0.3 already installed in Thonny, leaving users broken after an upgrade.
